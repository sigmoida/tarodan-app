# 20 — API Değişiklik Güncesi (2026-09-17): Üyelik ödemeleri ayrı PayTR mağazasında

> **Bu dosya bir delta raporudur.** Önceki günce `19-api-delta-2026-09-02.md`.
> Konu tek: PayTR non-3D (kullanıcısız recurring) yetkisini pazaryeri
> mağazasına vermedi. Üyelik ödemeleri — ilk satın alma **ve** oto-yenileme —
> non-3D yetkili **ayrı bir PayTR mağazasında** alınır. Sipariş, sepet, takas,
> öne çıkarma ve satıcı transferleri pazaryeri mağazasında kalır. Önceki mobil

## Neden kırıcı

Kart token'ları (utoken/ctoken) PayTR'da **mağazaya özeldir**. Pazaryeri
mağazasında saklanmış bir kart üyelik mağazasında çekilemez, tersi de. Sunucu
direct-form'da kayıtlı kartı artık ödemenin mağazasıyla birlikte arar.

**Kart taşıma yoktur.** Geçişten önce saklanmış kartlar pazaryeri mağazasında
kalır (sepet ödemesinde kullanılmaya devam eder) ama oto-yenilemede kullanılamaz.
Oto-yenilemesi açık üyeler geçişte bildirim alır; yenileme zamanı gelip üyelik
mağazasında kullanılabilir kartı olmayan üyenin oto-yenilemesi kapatılır ve aynı
bildirim gönderilir.

## Sözleşme

### `GET /payments/config` (public)

Üst düzey alanlar **eski anlamlarını korur** (eski sürümler bozulmaz);
yeni `purposes` alanı eklendi.

```ts
{
  bypassEnabled: boolean;
  cardStorageEnabled: boolean; // = purposes.checkout.cardStorageEnabled
  recurringEnabled: boolean; // = purposes.membership.recurringEnabled
  purposes: {
    checkout: {
      cardStorageEnabled: boolean;
      recurringEnabled: false;
    }
    membership: {
      cardStorageEnabled: boolean;
      recurringEnabled: boolean;
    }
  }
}
```

### `GET /membership/cards[?purpose=checkout|membership]`

- `purpose` verilirse yalnız o amacın mağazasındaki aktif kartlar döner.
- Verilmezse (eski sürüm) tüm aktif kartlar döner.
- Geçersiz değer → `400` (doğrulama).
- Her karta yeni alan: `purpose: "checkout" | "membership"`.
- `autoRenewEligible` artık `purpose === "membership" && !requireCvv`.

### `POST /payments/direct-form`

İstek gövdesi değişmedi. Davranış:

- Mağaza ödemenin hedefinden türetilir (üyelik siparişi → üyelik mağazası);
  istemci mağaza seçmez. Dönen `fields` içindeki `merchant_id` buna göre değişir —
  istemci alanları olduğu gibi `https://www.paytr.com/odeme`'ye POST etmeye
  devam eder.
- `saveCard` gönderilmezse: üyelik ödemesinde **kart saklanır**, diğerlerinde
  saklanmaz. Kullanıcı kutuyu kaldırdıysa `saveCard: false` gönderin.
- `savedCardId` yalnız ödemenin mağazasındaki kartı bulur.

### `PATCH /membership/auto-renew { autoRenew: true }`

Kural aynı, tanım daraldı: CVV istemeyen, **üyelik mağazasındaki** aktif kart
yoksa `400 server.membership.autoRenewCardRequired`. Mobil, bu hatada kullanıcıyı
üyelik ödemesiyle kart eklemeye yönlendirmelidir (ayrı "kart ekle" ucu yoktur;
kart bir üyelik ödemesinde `saveCard: true` ile saklanır).

### Bildirim: `membership_renewal_card_required`

```ts
{
  type: "membership_renewal_card_required";
  data: {
    tierName: string;
  }
}
```

Hedef: `/membership`. Başlık/metin sunucuda yerelleştirilir
(`server.notification.membershipRenewalCardRequired.*`).

## Değişmeyenler

- 3D Secure akışı, form alanları, `merchant_ok_url` / `merchant_fail_url`.
- Sepet, takas, öne çıkarma ödemeleri ve iadeleri.
- Geçiş öncesi alınmış üyelik ödemelerinin iadesi eski (pazaryeri) mağazadan
  yapılır — istemcinin yapacağı bir şey yok.
