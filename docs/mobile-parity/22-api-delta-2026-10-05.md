## 1. Yeniden-onay kapısı (yeni uçlar)

```
GET  /consents/me/pending   → { pending: [{ document, version, reason, path }] }
POST /consents/me/accept    { documents: ["terms","privacy","kvkk"] } → { pending: [...] }
```

- `pending` boşsa hiçbir şey gösterme. Doluysa kullanıcı uygulamayı kullanmadan
  önce her belge için bir kutu işaretler; metin bağlantısı web'deki `path`
  (`https://tarodan.com.tr{path}`) — mobilde in-app tarayıcıyla açın.
- `reason: "outdated"` → "Sözleşmelerimiz güncellendi" metni; `"missing"` →
  "Onayınız gerekiyor".
- Kabulden sonra dönen `pending` boşsa kapı kapanır. Yalnız `terms`, `privacy`,
  `kvkk` gönderilebilir; başka anahtar `400 server.consent.documentNotAcceptable`.
- Google/Apple ile yeni açılan hesap da ilk açılışta bu kapıya düşer (sosyal
  girişte onay kutusu yok).
- Sunucu, bekleyen onayı olan kullanıcının diğer isteklerini **reddetmez** —
  kapı istemcidedir. Web'de aynı kapı var (`ConsentGate`, `RequiredStepsGate`
  içinden; kimlik ekranından ÖNCE gelir — bkz. `23-api-delta-2026-10-05-legal-identity.md`).
- Belge adları için i18n: `legal.termsTitle`, `legal.privacyTitle`,
  `legal.kvkkTitle`; kapı metinleri `legal.consentGate.*`.

## 2. Kayıt: `acceptedConsents` (additive)

`POST /auth/register` gövdesine opsiyonel `acceptedConsents: string[]`.
Kullanım şartları + gizlilik kutusu → `"terms","privacy"`; **ayrı** KVKK kutusu
→ `"kvkk"`. Her biri ayrı kayıt olur. Sürüm/zaman sunucuda damgalanır. i18n:
`auth.termsAgreeRich`, `auth.kvkkAgreeRich`, `auth.mustAcceptKvkk`.

## 3. Mesafeli satış: ödeme formu kapısı

`POST /payments/direct-form` gövdesine opsiyonel `distanceSalesAccepted:
boolean`. Bu uç her satın almanın PayTR'den önceki son adımı olduğu için onay
burada da kabul edilir:

- Sepet checkout'unda `distanceSalesAccepted: true` gönderildiyse kayıt
  zaten vardır; direct-form'da tekrar göndermek zararsızdır (ikinci satır yok).
- **Teklif siparişinin** checkout adımı yoktur: onay yalnız direct-form'da
  gönderilebilir. Ödeme ekranında sözleşme kutusu zorunlu olmalı.
- Sunucu zorlaması `distance_sales_consent_required` platform ayarıyla açılır
  (**varsayılan kapalı**). Açıkken kaydı olmayan ve onay göndermeyen satın alma
  `400 server.consent.distanceSalesRequired` alır. Bu ayar mobilin P0
  sürümü yayıldıktan sonra açılacaktır.
- Takas ücreti ve üyelik ödemeleri kapıya girmez.

## 4. Pazarlama izni

Değişen uç yok. `PATCH /users/me/settings` içindeki
`marketingEmails` değişince sunucu tarihli onay/geri çekme kaydı yazar ve bülten
listesini hizalar (önceden liste güncellenmiyordu).

## 5. Web gateway'i (mobili etkilemez)

Web, tarayıcı IP'sini `x-tarodan-client-ip` başlığıyla taşır; API bu başlığa
yalnız iç ağdan gelen istekte güvenir. Mobil API'yi doğrudan çağırdığı için
IP bağlantıdan okunur; mobil bu başlığı **göndermemeli** (gönderse de yok sayılır).
