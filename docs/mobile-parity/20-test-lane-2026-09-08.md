# 20 — Canlı Test Şeridi: Mağaza İncelemesi ve Mobil QA Hesapları (2026-09-08)

> Apple App Review / Google Play incelemesi ve mobil QA **canlı ortamda**,
> canlı API'ye karşı yapılır. Bunun için API'de izole bir **test şeridi** var:
> süper-admin'in açtığı `isTestAccount=true` hesaplar. **Mobil uygulamada kod
> değişikliği gerekmez**; bu dosya test hesabıyla neyin farklı davrandığını ve
> inceleme notlarına ne yazılacağını anlatır.

## 1. Şerit kuralları (API tarafı, mobil için bilgi)

| Konu                    | Test hesabı için davranış                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| Görünürlük              | Test satıcısının ilanları canlı vitrin/arama/ES'te **yok**; test alıcısı **yalnız** test satıcılarını görür     |
| Arama                   | Test hesabı için arama ES yerine Postgres'ten döner; sonuç şekli aynı, sıralama/öne çıkarma daha basit olabilir |
| Etkileşim               | Canlı ↔ test arasında sepet/checkout/teklif/takas/DM **403** (`server.user.laneMismatch`)                       |
| Ödeme                   | PayTR formu `test_mode=1` ile açılır; **PayTR test kartı** ile ödenir, tahsilat yok                             |
| Kargo                   | Sürat'a gönderi açılmaz; takip numarası `TEST##########`, sağlayıcı mesajı `test_lane_no_dispatch`              |
| Kargo takibi            | Takip senkronu test kolilerini sorgulamaz → sipariş "kargolandı"da kalır; teslim, alıcının **teslim onayı** ile |
| e-Fatura                | eLogo belgesi üretilmez; fatura ekranı boş kalır                                                                |
| Satıcı ödemesi (payout) | Oluşmaz                                                                                                         |
| Raporlar                | Admin finans/dashboard test kayıtlarını saymaz                                                                  |
| Doğrulama               | Hesap e-posta/telefon doğrulanmış açılır; SMS/e-posta OTP akışına girmez                                        |

`GET /users/me` yanıtında `isTestAccount: boolean` alanı gelir. Mobil isterse
bununla küçük bir "Test hesabı" rozeti gösterebilir (zorunlu değil).

## 2. Ödeme: PayTR test kartı

Test şeridinde PayTR canlı merchant'ta test modu çalışır. Ödeme sayfasında
PayTR'nin yayınladığı test kartı kullanılır (kart bilgileri PayTR paneli →
Test Kartları; uygulamaya gömülmez). 3D Secure adımı test modunda da gelir.

Test hesabı **gerçek kartla ödeme yapamaz**: callback'teki `test_mode` bayrağı
ödemenin şeridiyle eşleşmezse API bildirimi reddeder, sipariş `pending_payment`
kalır.

## 3. Sipariş akışı testte nasıl ilerler

1. Test alıcı ilanı sepete atar → quote → checkout → PayTR test kartı.
2. Sipariş `paid` olur; satıcı "kargoya verdim" der → `TEST…` takip kodu.
3. Kargo takip ekranı hareket göstermez (sağlayıcıya gidilmedi).
4. Alıcı **teslim aldım** der → sipariş `delivered` → escrow süreleri normal işler.
5. İade/takas akışları da aynı şekilde çalışır; iade kargosu yine `TEST…` kodludur.

Süre bağımlı adımlar (escrow, otomatik teslim, teklif/takas süreleri) admin
**Sistem → Test Araçları → Süre Ayarlama** ile ileri alınabilir.

## 4. Mağaza inceleme (App Review) hesabı

Admin **Sistem → Test Araçları → Test Şeridi** kartından:

1. Bir **satıcı** test hesabı aç (`isSeller=true`), uygulamadan 3-5 ilan gir.
2. Bir **alıcı** test hesabı aç; adres otomatik gelir (İstanbul, sahte).
3. App Store Connect / Play Console **Review Notes**'a alıcı hesabın e-posta ve
   şifresini yaz; şunu ekle: _"Bu hesap yalıtılmış bir test şeridindedir;
   ödemeler PayTR test modunda çalışır, tahsilat yapılmaz; kargo takip
   numaraları sahtedir."_ PayTR test kartı bilgisini de nota ekle.
4. İnceleme bittiğinde **Şeridi sıfırla**: siparişler/ödemeler/takaslar silinir,
   hesaplar ve ilanlar kalır, satılan ilanlar yeniden satışa açılır.

Aynı hesaplar iç QA için de kullanılır. Hesap silme/kapatma istenmez; şifre
değişikliği normal akışla yapılır.

## 5. Sınırlar

- Test hesabı canlı ilanları **göremez** (bilinçli: sızıntı yüzeyi yok). Tam vitrin
  deneyimi için satıcı test hesabına yeterli ilan girilmeli.
- Vitrin/koleksiyon rayları test ilanlarını öne çıkarmaz; kategori ve arama
  sonuçları test şeridinde çalışır.
- Push bildirimleri, e-postalar ve uygulama içi bildirimler normal gider.
- Üyelik satın alma ve öne çıkarma paketleri de test modunda ödenir; oto-yenileme
  test modunda kalır.
