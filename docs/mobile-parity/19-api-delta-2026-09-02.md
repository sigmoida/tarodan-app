## Neden kırıcı

`isRequired` bayrağı bugüne dek yalnız admin tarafında (grubun silinme/pasife
alınma koruması) okunuyordu. Artık **ürün yazma yolu** da okur: `POST /products`
her zaman, `PATCH /products/:id` ise `attributes` alanı gönderildiğinde, aktif
ve en az bir aktif değeri olan her zorunlu genel özel grubun seçimde temsil
edilmesini şart koşar. Canlıda "Nadirlik/Bulunabilirlik" zorunlu işaretlidir.

**Geçiş:** mobil bu grubu gösterene kadar admin, grubun "zorunlu" işaretini
kaldırabilir; bayrak canlı okunur, deploy gerekmez. Mobil sürüm yayınlanınca
işaret geri açılır.

## Sözleşme

### `GET /products/attribute-groups[?manufacturer=:slug]`

Ölçek/malzeme/renk dahil tüm aktif genel gruplar + (verildiyse) üreticiye
bağlı gruplar. Gizli gruplar (`vehicle_type`) dönmez. Yeni alan:
`selectionMode: "single" | "multi"`.

```ts
Array<{
  slug: string;
  name: string;
  description: string | null;
  isRequired: boolean;
  manufacturerSlug: string | null;
  selectionMode: "single" | "multi";
  attributes: Array<{ slug: string; label: string; color: string | null }>;
}>;
```

Form kuralı: `manufacturerSlug == null && slug ∉ {scale, material, color}` →
genel özel grup → **tek seçimli** alan, `isRequired` ise yıldızlı ve zorunlu.
`manufacturerSlug === seçili üretici` → üreticiye bağlı grup → çoklu seçim
(mevcut davranış).

### `POST /products` ve `PATCH /products/:id` — `attributes: string[]`

- Genel + üreticiye bağlı tüm özel grup seçimlerinin düz slug listesi (değişmedi).
- Genel özel grupta birden fazla slug → `400 server.product.attributeGroupSingleSelect`
  (`{groups}`: grup adları).
- Zorunlu genel özel grup eksik → `400 server.product.requiredAttributeGroups`
  (`{groups}`: grup adları). `POST`'ta her zaman; `PATCH`'te yalnız `attributes`
  gönderildiğinde.
- Ölçek/malzeme/renk slug'ları `attributes` içinde **yok sayılır** (kendi
  alanları var); `attributeIds` zorunluluğu karşılamaz.
- `PATCH` + `attributes`: sunucu ilanın **tüm** özel grup bağlarını (genel +
  üreticiye bağlı) listeyle değiştirir. Eskiden yalnız üreticiye bağlı bağlar
  sıfırlanıyordu; genel bir grubun seçimi geri alınamıyordu. `attributes: []`
  = hepsini temizle.
- Yanıt: `attributes`/`colors` yalnız değiştiğinde de taze `attributes[]` döner
  (eskiden bayat kalabiliyordu).

### `GET /products/filters[?manufacturer=:slug]` — `customAttributes`

Üreticisiz çağrıda da döner: genel özel gruplar. `manufacturer` verilince
üreticiye bağlı gruplar eklenir. Alanlar `attribute-groups` ile aynı
(`description` hariç). `attrGroups` filtresi genel gruplarla da çalışır.

### Hata gövdesi

Diğer i18n hatalarıyla aynı: `{ statusCode: 400, message: { i18nKey, i18nParams } }`
→ istemci `Accept-Language` ile çevrilmiş metni alır.

## Doğrulama listesi (mobil)

1. Zorunlu genel grup boşken ilan oluştur → alan altında hata, istek atılmaz.
2. Seçimle oluştur → detayda satır görünür.
3. Düzenle → değer önceden seçili; kaydet → korunur; değiştir → eski bağ silinir.
4. Üretici değiştir → genel seçim kalır, üreticiye bağlı seçimler düşer.
5. Kenar çubuğunda üretici seçmeden Nadirlik filtresi çalışır.
