## 1. Takas fiyatlama v2: komisyon gitti, iki taraf da ödüyor ⚠️ KIRICI

**Kalıcı referans: `docs/PAYMENTS.md` §8 "Takas ödemeleri (v2)"** — model orada
uzun anlatılıyor; burada mobil sözleşme özetleniyor.

**Eski (v1):** tek para kalemi nakit farktı; tek `cashPayment` kaydı vardı,
yalnız `cashPayerId` öderdi, fark üzerinden %'lik aracılık komisyonu + KDV
eklenirdi. Eşit takasta hiç ödeme olmaz, kabulden sonra doğrudan kargoya geçilirdi.

**Yeni (v2):** **iki taraf da her zaman öder**:
`hizmet bedeli + (2 × kargo) + (varsa o tarafın borçlu olduğu nakit fark)`.

- Hizmet bedeli, komisyon kurallarından okunan **ürün başına sabit, KDV dahil**
  tutarların toplamı (verdiğin her ürün için satıcı bedeli, aldığın her ürün
  için alıcı bedeli). Oran/komisyon yok.
- Kargo = tarafın toplam desisine denk gelen paket kademesi tutarı × **2 bacak**
  (üye → depo, depo → üye). Paket kademeleri için `14-shipping-package-tiers.md`.
- Sürüm, takasın üstünde damgalı (`Trade.pricingVersion = "v1" | "v2"`), yeni
  her takas v2 açılır; eldeki takaslar açıldıkları modelle biter. **Ama bu alan
  `TradeResponseDto`'da YOK** — istemci v2'yi şöyle anlar: kabul sonrası
  `cashPayments.length === 2`, veya kabul öncesi `GET /trades/:id/payment-quote`
  boş olmayan gövde döndürüyor.

### 1a. `GET /trades`, `GET /trades/:id` ve tüm yaşam-döngüsü yanıtları

Liste ve detay aynı mapper'dan geçer; ikisinde de **yeni alan**:

```jsonc
"cashPayments": [ // her zaman var; kabulden önce []
  {
    "id": "…",
    "payerId": "…",           // bu satırı ödeyen taraf
    "recipientId": null,       // ⚠️ artık string|null — yalnız fark taşıyan satırda dolu
    "amount": 500,             // nakit fark; borçlu olmayan tarafın satırında 0
    "tradeFeeAmount": 120,     // YENİ: hizmet bedeli (KDV DAHİL)
    "shippingAmount": 190,     // YENİ: bu tarafın 2 bacaklık kargo bedeli
    "commission": 0,           // v1 kalıntısı; v2 satırlarında her zaman 0
    "totalAmount": 810,        // PayTR'nin çektiği = amount + tradeFeeAmount + shippingAmount
    "status": "pending",       // pending | completed | refunded | …
    "paidAt": null
  },
  { /* karşı tarafın satırı */ }
]
```

- **Tekil `cashPayment` alanı duruyor** (bilinçli olarak, eski mobil istemci
  için): v2'de "birincil" satır = fark taşıyan satır, yoksa ilk satır.
  Ama üzerinde `commission = 0` ve `totalAmount ≠ amount + commission` artık —
  **`amount + komisyon`dan toplam türeten her hesap v2 takasta yanlıştır.**
- `cashCommission` v2 takasta her zaman `undefined` — "komisyon" satırını
  v2'de hiç çizme.
- `cashAmount` / `cashPayerId` değişmedi (ham fark ve borçlusu).
- `paymentDeadline` v2'de **eşit takas dahil her kabul**de set ediliyor.

### 1b. Akış değişikliği: kabul → herkes ödeyene kadar bekleme ⚠️

`TradeStatus` enum'una **yeni değer eklenmedi**; yönlendirme değişti:

- **Kabul (v2): her zaman → `awaiting_payment`** — eşit takasta bile. Eski
  "fark yoksa doğrudan `shipping_to_warehouse`" varsayımı v2'de kırılır.
- Kabul anında iki `cashPayments` satırı, tutarlar **snapshot'lanarak** yaratılır
  (kural/tarife sonradan değişse de tutar sabit).
- **`shipping_to_warehouse`'a geçiş yalnız TÜM satırlar `completed` olunca.**
- Taraf bazlı "ben ödedim mi?" sinyali ayrı bir alan değil: `cashPayments`
  içinde `payerId === benimId` satırının `status`'üne bak. "1/2 ödendi" =
  takas `awaiting_payment` + benim satırım `completed` + karşı satır `pending` —
  bu **takılma değil**, meşru ara durum ("karşı tarafın ödemesi bekleniyor").
- `paymentDeadline` dolarsa ve tek taraf ödediyse takas otomatik iptal olur,
  ödeyen iade alır.

### 1c. YENİ — `GET /trades/:id/payment-quote`

- Bearer; takası görebilen taraflar çağırabilir. Takasın **her durumunda**
  çalışır: kabul öncesi canlı önizleme (güncel kural + tarife), kabul sonrası
  bilgi amaçlı (asıl tutarlar `cashPayments`'ta snapshot).
- **v1 takasta `200` + boş gövde döner** — boş gövdeyi ele al.
- `503 server.shipping.noActiveTariff`: aktif tarifede paket kademesi yoksa.

```jsonc
{
  "tradeId": "…",
  "initiator": {
    "userId": "…", "side": "initiator",
    "serviceFee": 120, "shipping": 190, "cashDifference": 500, "total": 810,
    "feeLines": [ { "productId": "…", "role": "seller", "amount": 60 }, … ]
  },
  "receiver": { /* aynı şekil */ }
}
```

`total = serviceFee + shipping + cashDifference`; hepsi TL ve KDV dahil.
`feeLines` denetim detayıdır; ekranda `serviceFee` tek satır gösterilir.

### 1d. YENİ — `POST /trades/payment-quote/preview`

Teklif/karşı-teklif **kaydedilmeden** iki tarafın maliyetini fiyatlar
(teklif oluşturma ekranında canlı döküm için). Bearer zorunlu.

```jsonc
// istek
{
  "initiatorItems": [{ "productId": "…", "quantity": 1 }],
  "receiverItems": [{ "productId": "…" }],
  "cashAmount": 500, // opsiyonel, >= 0
  "cashPayer": "receiver", // opsiyonel; varsayılan "initiator"
}
// yanıt: { "initiator": {…}, "receiver": {…} } — §1c'deki taraf şekli,
// tradeId/userId/side alanları olmadan
```

Bilinmeyen/silinmiş `productId` sessizce atlanır. Tutarlar tahminidir; kabul
anında kilitlenir. Bu uç **takas** teklifleri içindir — ilana fiyat teklifi
(`/offers`) akışıyla ilgisi yok, o akış değişmedi.

### 1e. Ödeme uçları: "belirlenen ödeyici" → "çağıranın kendi satırı" ⚠️

Yeni ödeme ucu yok; mevcut ikisi yeniden kapsamlandı:

- **`POST /trades/:id/cash-payment/initiate`** (eşdeğeri
  `POST /payments/initiate-trade-cash` gövde `{ tradeId }`): v2'de ödeyici,
  `cashPayments` içinde **çağıranın kendi satırı**dır — eşit takasta bile iki
  taraf da çağırır. Eski "fark yoksa 400 / ödeyici değilsen 403" davranışları
  v2'de kalktı (v1 takasta sürüyor); bu hatalara bağlanmış mobil mantık v2'de
  geçersiz. Durum kapısı: `accepted | awaiting_payment`. Hatalar:
  `400 server.payment.cashPaymentRecordNotFound` (çağıranın satırı yok),
  `400 server.payment.tradeCashPaymentAlreadyCompleted`. Yanıt:
  `{ paymentId, provider: "paytr", expiresIn: 300, tradeId, amount }` —
  `amount` = çağıranın kendi `totalAmount`'ı. Tekrar çağrı güvenli.
- **`POST /payments/direct-form`** (kayıtlı kart / Direct API form alanları;
  gövde `{ tradeId, paymentId?, savedCardId?, saveCard?, provider? }`): aynı
  şekilde artık çağıranın kendi satırını çözer — eşit takas tarafları kartla
  ödeyebilir.
- **`GET /payments/:id/status`** takas ödemelerinde **yeni `pricing` nesnesi**
  döndürüyor: `{ serviceFee, shippingAmount, cashDifference, totalAmount }` —
  dökümü istemcide türetme, bunu bas.

Ödeme tamamlanması yine asenkron (PayTR callback); eskisi gibi
`GET /payments/:id/status` ile beklenir.

### 1f. İade matrisi (iptal/ret anına göre)

Her taraf **kendi ödemesi üzerinden bağımsız** iade alır:

| Aşama                                                          | Ödenen satır başına iade                                                                        |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Hiçbir ürün kargoya verilmeden (iptal/ret/deadline)            | **Tam iade** (`totalAmount`)                                                                    |
| Herhangi bir bacak kargoya verildikten / depoya varıştan sonra | `totalAmount − shippingAmount` — **kargo yanmaz sanma: kargo İADE EDİLMEZ**, bedel + fark döner |
| Takas `completed`                                              | İade yolu yok; yalnız ihtilaf süreci                                                            |

Eşik, kullanıcının iptal edebilme kilidiyle aynıdır: "hâlâ iptal edebiliyorsan
kargon da geri gelir." Kargo kesintisi ekran metni için `trade.shippingNotRefundable`
anahtarı var. Nakit fark karşı tarafa emanet/hakediş yoluyla gider; bedel ve
kargo platformda kalır.

### 1g. Takas i18n anahtarları (paylaşılan katalogda hazır)

## 2. Mesafeli satış sözleşmesi onayı: `distanceSalesAccepted` (additive)

`POST /orders/checkout` ve `POST /orders/checkout/guest` gövdesine
**opsiyonel** `distanceSalesAccepted?: boolean` eklendi.

- **Kırıcı değil**: göndermeyen eski istemci aynen çalışır, sadece onay kaydı
  düşmez. Sunucu zorlamıyor; "kutucuğu işaretle" zorunluluğu istemci UI'ındadır.
- `true` gönderildiğinde sunucu **tarihi ve sözleşme sürümünü kendisi damgalar**
  (istemci sürüm göndermez); yanıtta **geri dönmez** (salt denetim kaydı).
- **İlk çağrıda gönder**: idempotency replay'i sonradan gelen onayı işlemez.
- Kapsam dışı: `POST /orders/buy` (buy-now), `POST /orders/guest` (legacy tekil
  misafir), teklif/takas ödemeleri, üyelik/boost. Mobil buy-now bugün
  `/orders/buy` kullanıyorsa onay kaydı düşemez — web'in yaptığı gibi tek
  ürünlük `POST /orders/checkout`'a geçmeyi değerlendirin.
- Web'in onay metni için i18n: `checkout.distanceSalesConsent`,
  `checkout.distanceSalesRequired`.

## 3. Sepette satır seçerek ödeme: API değişikliği YOK

Web artık sepetin alt kümesini ödetebiliyor; bunun tamamı istemci durumu.
`POST /orders/quote` ve `POST /orders/checkout` zaten gönderilen `items`
listesini fiyatlar/tahsil eder ve **yalnız o ürünleri** sepetten düşer. Mobil
aynı özelliği sıfır API işiyle yapabilir. İlgili i18n: `cart.selectItem`,
`cart.selectAll`, `cart.selectItemsToCheckout`.

⚠️ Buradan çıkan ders (web'de düzeltilen bug): sunucu, sipariş verilen satırları
**checkout transaction'ının içinde** sepetten siler. Mobil, başarılı checkout
sonrası ayrıca `DELETE /cart/items/...` atıyorsa `404 "Ürün sepette bulunamadı"`
alır — silme yerine sepeti **yeniden çek** ve sepet temizliği hatasının ödeme
yönlendirmesini asla düşürmesine izin verme.

## 6. Bülten aboneliği: yeni 400

`POST /newsletter/subscribe` gövdesi `{ email, newsletter?, promotions? }`;
bayraklar gönderilmezse ikisi de `true` varsayılır (değişmedi). **Yeni:** ikisi
de açıkça `false` gönderilirse artık `400` ("En az bir e-posta tercihi
seçmelisiniz." — hata metni şimdilik sabit Türkçe string). Mobilde bülten
formu varsa: kutular **işaretsiz başlasın** (KVKK/ETK), en az biri seçilmeden
gönderme. Ayrıca kayıttaki `marketingConsent` artık gerçekten kalıcı yazılıyor
ve `unsubscribe` uçları kullanıcının pazarlama iznini de kapatıyor
(sözleşme değişikliği yok).

## 7. Ufak davranış notları

- **`GET /products/filters`**: `scales` boş katalogda artık **boş dizi**
  dönebilir (16'lık sabit fallback kaldırıldı); `materials` fallback'i duruyor.

  mobil ekip bu uçları çağırmadığını teyit etsin; şifre akışı `/auth/*`

- Web ödeme sayfası CSP'ye alındı ve PayTR'ye **iframe'siz** form POST'u
  yapıyor (`frame-ancestors 'self'`) — web ödeme sayfasını iframe içinde
