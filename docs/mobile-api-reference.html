Mobil uygulama için eksiksiz API sözleşmesi

Bu belge API controller’larını ve web istemcisinin işlev yüzeyini tarar. Mobil uygulama ayrı bir repoda yönetilir; bu katalog mobil implementasyon durumunu ölçmez, uygulanması gereken sunucu sözleşmesini tanımlar.

Kapsam ve güvenlik sınırı

Admin, dev/test, health ve provider callback/webhook uçları mobil sözleşmeye dahil edilmez. Public uçlar tokensız; diğer tüm uçlar Authorization: Bearer <ACCESS_TOKEN> ister. PayTR callback’leri yalnız sağlayıcı içindir.

Mobil işlev akışları

Mobil ekranların endpointleri tek tek değil, bu uçtan uca iş akışlarını tamamlayacak şekilde kullanması gerekir.

Mobil durum sözlükleri

Mobil filtre, rozet, aksiyon görünürlüğü ve polling kararları bu backend enum değerleri üzerinden çalışmalıdır.

Web işlev paritesi için zorunlu uçlar

Web üretim kodunda kullanılan tüketici uçları mobil uygulamanın işlevsel kapsamına dahildir. Harici mobil repo bu listeyi kendi implementasyon ve kabul testleriyle doğrulamalıdır.

Ortak istemci sözleşmesi

Web BFF cookie kullanır; native istemci access/refresh token çiftini işletim sisteminin güvenli depolamasında tutmalıdır.

Base URL ve auth

  • Production: MOBILE_API_BASE_URL=<PRODUCTION_API_ORIGIN>/api
  • Preview: MOBILE_API_BASE_URL=<PREVIEW_API_ORIGIN>/api
  • Local iOS: http://localhost:3001/api; Android emulator: http://10.0.2.2:3001/api.
  • Bearer token her korumalı isteğe eklenmelidir.
  • 401’de tek-uçuş POST /auth/refresh uygulanmalı ve rotated refresh token atomik olarak saklanmalıdır.
  • POST /auth/login başarılı parola sonrası requires2FA: true dönerse token henüz verilmemiştir; aynı istek 6 haneli TOTP veya XXXX-XXXX yedek kodla twoFactorCode alanında tekrarlanmalıdır.
  • 2FA etkin hesaplarda Google/Apple girişi token üretmez; istemci parola + ikinci faktör akışına yönlendirmelidir.
  • USER_BANNED 403 tam ekran ban akışına yönlendirir.

İstek ve hata modeli

  • JSON isteklerinde Content-Type: application/json.
  • Dosya uçlarında multipart/form-data; Content-Type boundary istemci tarafından üretilir.
  • 400 validation, 401 session, 403 yetki/ban, 404 kaynak, 409 yarış/idempotency olarak ele alınır.
  • Mutation sonrası ilgili TanStack Query anahtarları invalidate edilir.

Ödeme ve guest kuralları

  • Guest uçlarında auth interceptor içermeyen guestApi kullanılır.
  • POST /orders/quote isteği ürün adedi ve varsa kupon kodunu içerir.
  • Quote’taki pricingHash ve shippingTariffVersion, checkout isteğine değiştirilmeden geri gönderilir.
  • Ekrandaki ara toplam, kargo, vergi ve nihai tutar quote pricing alanından gösterilir; istemci hesabı otorite değildir.
  • 409 PRICING_CHANGED sonrasında quote yenilenir ve kullanıcı güncel tutarı yeniden onaylar.
  • PayTR sonucu yalnız callback ile kesinleşir; mobil status endpointini poll eder.
  • Ödeme başlatma yanıtındaki paymentAccessToken güvenli depoda tutulur ve public ödeme uçlarına X-Payment-Capability olarak eklenir.
  • Mutation tekrarlarında checkout/idempotency anahtarı korunur.

Endpoint kataloğu

“Web paritesi için zorunlu” filtresi web istemcisinde kullanılan uçları; “API’de ek olarak mevcut” filtresi diğer tüketici uçlarını gösterir.

Realtime Socket.IO sözleşmesi

Socket base URL API originidir; handshake auth içinde access token taşınır. Oda katılımı sunucuda üyelik/sahiplik kontrolünden geçer.

Mobil mesajlaşma, bildirim, teklif, ürün ve sipariş ekranları aşağıdaki olayları desteklemelidir. Handshake yalnız access token kabul eder ve kullanıcının güncel ban/silinme durumunu doğrular. join:thread mesaj katılımcılığını, order:subscribe alıcı/satıcı sahipliğini sunucuda kontrol eder; typing olayları yalnız yetkili olarak katılınmış thread odasından gönderilebilir.
